# 구현 API ↔ 대시보드 연결 현황

기준: 2026-11-22. 현재 구현된 **29개 operation 모두 호출 경로를 화면에 연결**했다. 제품의 모든 설계 기능이 완성됐다는 의미가 아니다. 자동 장애 탐지·인증 등 미구현 API는 이 표에 포함하지 않는다. 모델 API의 실제 추론 검증은 별도이며 현재 학습 모델은 연결 전이다.

## 범위와 제한

- Service map은 직접 CLIENT→SERVER span 관계만 표시한다. 전체 서비스 토폴로지·RPS·원인 판정이 아니다. 60개 초과 서비스는 그래프를 생략하고 연결 표를 제공한다. 서비스 이름과 Deployment가 일치할 때만 서비스 상세 링크를 제공한다.
- 수집 최신성은 조회 시점 최근 30분에서 대표 신호의 시각을 확인한다. 요청 지표의 최근 샘플은 최근 요청 발생을 뜻하지 않는다. UNKNOWN/NO_DATA/STALE을 정상·장애로 바꾸지 않는다.
- 수집 최신성 API는 저장소를 순차 조회하므로 최대 timeout 합계 30초를 기다릴 수 있다. 이 호출만 35초 클라이언트 제한을 사용하고 나머지는 기존 20초다.
- 일반 설정은 환경 상세 및 health 조회다. 환경 수정 기능은 없다. health는 SentriX 서버·DB 상태이며 관측 대상의 정상 판정이 아니다.
- 설정 → 분석에서 환경 주기 실행을 시작·중지한다. 수동 장애 이력·분석 요청 상태·저장 결과 조회는 연결됐다. 자동 장애 탐지/CPU throttling/전체 상태 이력/인증/알림/평가 등은 미구현이며 예시 또는 미지원으로 남긴다.
- 새 외부 환경에 대한 일반화 검증 및 장시간 부하 검증은 별도다.

## 이번 검증

- 단위 테스트 19개 및 production build 통과. 기존 번들 500kB 경고 유지.
- 실제 Java/MySQL/Prometheus/Loki/Tempo 연동: 서비스 수집 최신성 4종, 부분 Tempo 응답의 UNKNOWN 표시 확인.
- 저장된 실제 상품 조회 trace에서 3개 서비스·2개 연결 확인. Trace 상세 6개 span과 호출 관계 화면 왕복 이동 확인.
- 설정 일반에서 실제 Online Boutique 환경 상세와 health UP 표시 확인. 검증 탭 오류 로그 없음.
- 기존 기능의 검증 기록은 README 및 sentrix-core/docs/BACKEND-TRACKER.md 참조. 이번 작업에서 모든 저장 API를 재실행하거나 사용자 설정을 변경하지 않았다.

## 수동 분석 실행 준비·저장 결과 (2026-11-22)

| 상태 | API | 사용 화면 |
|---|---|---|
| [x] | GET E/incidents/{incidentId}/rca-jobs/{jobId}/result | 완료 작업 선택 → 저장된 판정·후보·근거 |

- 작업 상태 `BLOCKED_MODEL_UNAVAILABLE`, `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELLED`를 표시한다. 앞의 세 상태에서 취소할 수 있다.
- `기록·분석 새로고침`으로 이력과 선택한 작업/결과를 다시 조회한다. 화면·환경·작업 변경 시 이전 조회를 취소한다.
- 완료된 작업의 결과만 읽으며 작업/환경/namespace/분석 구간/계약·특징·모델 버전을 검증한다. NODE·EDGE 후보와 근거는 반환된 내용만 표시하고 점수를 확률로 표현하지 않는다.
- 기존 미연결 이력의 null metadata를 허용한다. 과거 미연결 요청은 모델 연결 후 자동 재실행하지 않는다.
- 모델 미연결 기본 동작은 유지한다. 이 연결은 실제 모델의 추론 성능이나 자동 감지를 검증한 것이 아니다.

검증: 프론트 단위 테스트 23개 및 production build 통과. `scripts/check-analysis.mjs`의 브라우저 API fixture로 6개 상태·취소·저장 결과/보류·다른 환경 응답 거부·늦은 결과 차단·근거 escaping을 확인했다. 실제 모델 추론 검증과 구분한다. 기존 번들 크기 경고 유지.

- 2026-11-22 실제 Java/MySQL 연동: 대시보드5176에서 검증용 수동 기록의 분석 요청→미연결·고정30초 구간 표시→취소→수동 종료를 확인했다. 서버 API에서도 CANCELLED/USER_CANCELLED 및 결과409 확인. 모델 성공 결과는 fixture로만 검증했고 실제 모델 추론은 미검증이다.

### 전시 화면과 관측 데이터 · 2026-11-24

전시 주소의 개요는 Vercel 배포 화면의 배치에 맞춰 장애 배너, 주요 지표, Anomaly score와 Service map, 서비스 타임라인과 요청 지표, 최근 장애를 표시한다. 이상 점수는 Java overview의 recentWindows에서 읽는다. 관측한 호출만 지도에 그린다. 일반 환경의 미니 맵은 최근 Trace 한 건을 사용한다. 재현 환경은 같은 시각까지 확보된 실험 경로를 사용한다. 서비스별 정상·경고·이상 이력은 아직 미판정이다.

실험 시작은 큰 모니터의 현재 페이지를 이동시키지 않는다. 장애 상세에서 모델 후보를 선택하면 근거가 바뀌고, 지도 링크는 같은 작업의 순위를 연다. 11월 24일 저장된 실험을 재현한 검증에서 서비스 11개, 상품 조회 경로 1순위, 30초 구간별 분석과 정상 회복을 확인했다. 공용 Vercel은 예시 데이터를 제공한다.

### 2026-11-24 · 전시 개요의 동시 조회 축소

개요에 그리는 요청·오류·지연 지표만 요청한다. 서비스 상세에서 사용하는 CPU·메모리는 상세 화면에서 조회한다. 맥북 환경의 Prometheus 지연과 8080 실행 JAR의 클래스 로딩 오류를 확인했고, 독립 복사본으로 백엔드를 재기동한 후 5190에서 요청량·오류율·p99가 1분 이상 연속 조회되는 것을 확인했다.


### 2026-11-24 · 실시간 전시

맥북 실험실에서 장애를 주입해도 큰 모니터의 개요는 같은 운영 환경을 계속 본다. 전시 주소의 장애 상세는 Java가 저장한 분석 작업의 후보와 근거를 제품 디자인으로 표시한다. 첫 실시간 상품 조회 경로 지연 실험에서 개요 지표가 1분 이상 갱신됐고, 주입 전 모델은 이미 이상이었다. 주입 중에는 관측 조회 시간 초과와 표본 부족이 발생했다. 이 실험에서 해당 경로의 원인 순위는 확인되지 않았다.

### 2026-11-24 · 개요의 기간별 판정 이력

홈·서비스 상세·서비스 맵은 선택한 from/to를 overview API에 전달한다. 서비스 지표 이탈 점수와 환경 모델 점수, RED 차트는 같은 실제 환경 이상 구간을 분홍색으로 표시한다. 서비스 상태의 빨강은 1순위 후보, 노랑은 2~3순위 후보이며, 경로 후보는 양 끝 서비스에 표시된다. 보류와 기록 공백은 빗금이다. 공개 3시간 화면에서 이상 64개와 서비스 상태의 빨강 27구간·노랑 47구간을 브라우저로 확인했다.

### 2026-11-24 · Vercel 화면과 실시간 데이터 연결

전시판과 Vercel에서 19개 경로의 화면 구성을 대조했다. 공개 장애 상세에서 후보 목록 너비를 원본과 같은 약 260px(1440px 화면)로 맞추고 유형 태그, 큰 점수, 추이, Evidence, 관련 링크를 복구했다. 경로 후보는 출발·도착 서비스의 서버 p90을 각각 표시하고 노드 후보는 CPU 코어 사용량을 표시한다. 이는 호출 경로 자체의 span p90과 다른 관측값이므로 차트에 범위를 명시한다. 분홍 음영은 저장된 장애 발생~종료 범위다. 타임라인, Trace·로그 탭도 저장된 관측 기간을 기준으로 조회한다.

공통 상단 바, 서비스 상세의 패널 순서, 관리의 데이터 소스 목록·상태 화면을 정리했다. 공개 주소에서는 실제 데이터 소스 주소와 로그 원문을 노출하지 않는다. 공개 15개 경로의 렌더링, 장애 상세 탭 5개, 후보 전환, 상세 링크의 시간·서비스, 모바일 넘침, 데이터 소스 검색을 브라우저에서 검증했다.

### 2026-11-24 · 운영자 홈의 판정 범위

홈 상단은 열린 장애의 발생 시각, 최근 RCA의 1순위와 첫 근거를 표시한다. 그 아래 세 지표는 선택한 서비스의 요청량, 오류율, p99다. 점수 차트의 기본값은 환경 전체의 모델 점수(0~1)이며 서비스 지표 이탈(0~100)로 전환할 수 있다. 점선은 해당 모드의 기준이고 분홍 음영은 자동 분석의 이상 구간이다.

서비스 상태는 1분 간격으로 오류율·p99를 같은 서비스의 직전 60분 중앙값과 비교한다. 유효한 기준 표본이 45개 이상일 때 오류율이 2%p 이상 상승하면 빨강, p99가 1.5배 이상이면서 20ms 이상 상승하면 노랑이다. 두 지표가 기준 안이면 회색, 자료가 모자라면 빗금이다. 서비스 맵의 ①은 모델 1순위 서비스 또는 해당 방향의 호출 경로를 가리킨다.

2026-11-24 환경 점수 차트는 선택 기간 안에 끝난 같은 분석 구간에서 숫자와 최종 판정을 가져온다. 점수 기준 초과와 최종 이상 판정을 따로 표시한다. 분홍색은 저장된 이상 판정이고, 빗금은 점수가 없거나 중간 분석 기록이 비어 있는 구간이다. 빗금 위에 포인터를 두면 해당 시각과 저장된 사유가 표시된다. 결측 사이의 단독 점수는 점으로 그린다.

### Explore 서비스 선택과 조회 범위

로그와 Trace는 화면 상단의 서비스 선택기를 공유한다. 목록은 현재 환경의 `GET /api/v1/environments/{id}/services` 응답에서 가져온다. 홈과 실험실의 전시 대상 목록은 Explore 조회 범위를 제한하지 않는다. 서비스 변경 시 선택한 기간을 유지하고 이전 조회를 취소한다. Trace의 ‘시작 서비스’는 요청을 시작한 서비스이며, 조회 서비스는 해당 요청에서 조건에 맞는 span을 가진 서비스다.

공개 로그 화면은 시간·레벨별 집계 항목을, 운영자 화면은 원문 로그를 표시한다. 시드니에서 두 주소 모두 서비스 16개를 확인했고, redis-cart의 로그 집계·원문과 checkoutservice의 Trace 응답에서 요청한 서비스 이름을 확인했다.
